4/*
5 * cta_shm.h — the CTA request queue's shared-memory home.
6 *
7 * WHAT: one SHM zone holding ONE brix_cta_queue_t for the whole worker set,
8 * plus lock-taking wrappers around the pure-C queue operations.
9 * WHY: the queue used to be a per-worker `static brix_cta_queue_t *`. Every
10 * worker replayed the same journal, so every worker set next_id to the
11 * same value and then allocated from its own copy — TWO WORKERS HANDED
12 * OUT THE SAME REQUEST ID. A `query` or `cancel` for id 7 landed on
13 * whichever worker the connection happened to reach and could act on a
14 * different request than the one the client was told about. This retires
15 * the "cross-worker SHM queue is deferred" ADR in svc_cta/README.md.
16 * HOW: brix_shm_table_alloc() per INVARIANT 10 — the table is allocated FROM
17 * the slab pool (never laid over shm.addr, which nginx's SIGCHLD handler
18 * walks as an ngx_slab_pool_t) and the mutex is bound to the pool's own
19 * lock word, so a worker that dies holding it is recovered. The locking
20 * lives HERE and not in cta_queue.c, which stays pure C so that
21 * cta_queue_unittest.c keeps compiling with `gcc -Isrc` and no nginx.
22 *
23 * The journal fd is opened ONCE, during zone init, which runs in the master
24 * BEFORE fork — so every worker inherits the same open file description and
25 * its shared O_APPEND offset, and one journal serves the whole set. That is
26 * also why journal_append() emits each record with a single write(2): the
27 * atomicity of one append per record is what makes the sharing safe.
28 */
