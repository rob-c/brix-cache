70 /* ---- advertised extensions (phase-115 W5.2) ----------------------------
71 * `feat` is meaningful only once `feat_probed` is set: zero means either
72 * "not asked yet" or "asked, advertises nothing", and only the flag tells
73 * the two apart. See gftp_feat.h for why the probe is lazy.
74 *
75 * `cont` holds the CONTINUATION lines of the last multiline reply, which is
76 * where a FEAT reply keeps every feature it advertises — `text` gets only
77 * the terminator line, a bare "End". `cont_truncated` says the origin sent
78 * more than GFTP_CONT_CAP.
79 *
80 * What truncation MEANS is per-reader, and the two readers differ. For
81 * FEAT it fails safe on its own: a cut line cannot begin a new one, so
82 * truncation can only LOSE a feature, never invent one. For a SPAS reply
83 * (phase-115 W5.3) it would silently DROP STRIPES, and the receiver would
84 * then wait for EOD blocks on connections nobody opened — so gftp_spas.c
85 * refuses a truncated reply outright rather than reading what survived. */
86 unsigned feat;
87 int feat_probed;
88 int cont_truncated;
89 char cont[GFTP_CONT_CAP];

91 /* ---- striped data channel (phase-115 W5.3) -----------------------------
92 * How many data connections ONE retrieve may open, from the store line's
93 * `streams=<n>`; 1 (the default) means the driver never asks for a striped
94 * channel. Unlike want_mode/want_prot this is a CEILING rather than a
95 * requirement: striping changes how fast the same verified bytes arrive,
96 * not what they are, so an origin that cannot offer it is served by the
97 * single pinned connection instead of failing. See gftp_spas.h. */
