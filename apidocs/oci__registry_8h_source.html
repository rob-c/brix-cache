1/*
2 * oci_registry.h — seams internal to the local registry (push) surface (D4).
3 *
4 * WHAT: the store layout primitives, the authorization gate and the two
5 * write engines (upload sessions, manifest PUT) that `brix_oci_registry`
6 * composes. Nothing here is reachable from a mirror-only build path:
7 * the surfaces share a module, a classifier and an error envelope, and
8 * nothing else.
9 * WHY: the push surface is the one place in this plane where wire bytes
10 * become STORED objects, so its seams want to be visible in one header
11 * rather than discovered per file: every path in the store is built by
12 * oci_store.c from an already-validated name/digest (§0.7.2), every
13 * write lands through a staged temp, and every request has passed the
14 * one authorization gate before any of it runs. Splitting these into
15 * four translation units keeps each under the size cap and keeps the
16 * state machine (App. J.7) readable as a state machine.
17 * HOW: declarations only. The store speaks NUL-terminated C paths because
18 * that is what the VFS seam and the staged-file helpers take; the
19 * handlers speak nginx rcs.
20 */

29/* A manifest body is JSON describing an image; real ones are single-digit
30 * KiB. The cap is the spec's own guidance, and it is enforced BEFORE the
31 * body is read, so a hostile 100 MiB "manifest" never reaches jansson. */
32#define BRIX_OCI_MANIFEST_MAX (4 * 1024 * 1024)

83/* Publish `len` bytes durably at `path` under store `st`, creating the parent
84 * chain first (tag pointers, ref marks, manifests, index entries). The registry
85 * adapter over brix_service_publish_bytes (phase-108 C10): it carries the
86 * store-model glue (parent layout, st->root, the storage domain) the generic
87 * verb deliberately does not, and inherits the verb's typed domain claim,
88 * confined O_EXCL staging, per-domain data fsync and the C3 durable-publish
89 * barrier. `domain` is REGISTRY for durable objects, STAGE for reconstructible
90 * session markers. NGX_OK / NGX_ERROR (errno set). */

95/* Publish an already-written staged file at `stage_path` onto `final_path`
96 * (the sealed blob), CAS-exclusive: the rename is RENAME_NOREPLACE, so a
97 * concurrent seal of the same content-addressed digest resolves to a benign
98 * EEXIST the caller treats as success rather than a torn overwrite. Creates
99 * `final_path`'s parent chain first. NGX_OK, or NGX_ERROR with errno==EEXIST on
100 * the already-present path. The REGISTRY adapter over brix_service_publish_fd. */
