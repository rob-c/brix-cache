16/*
17 * WHAT: one entry's checksum request — where the entry lives (dirfd + name),
18 * how to name it in a log line, its already-taken stat, the algorithm,
19 * and the endpoint's phase-105 write posture.
20 * WHY: the digest cache writes an xattr ON THE EXPORT OBJECT (Appendix H.1),
21 * so the listing has to carry the caller's mutation policy down to the
22 * integrity layer rather than persisting unconditionally; bundling it
23 * also keeps the call at three parameters instead of nine.
24 * HOW: the caller fills one on the stack per entry; the token builder only
25 * reads it. `policy` zero-initialises to READ_ONLY, so a caller that
26 * forgets it recomputes the digest rather than writing to the export.
27 */
