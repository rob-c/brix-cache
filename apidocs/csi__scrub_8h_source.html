7/*
8 * fs/backend/csi_scrub.h — the paced background CSI scrub (phase-59 W2b).
9 *
10 * WHAT: An at-rest integrity sweep. brix_csi_scrub_file recomputes every
11 * recorded block CRC of one data file against its bytes on disk;
12 * brix_csi_scrub_walk recurses an export root, scrubbing each regular
13 * data file that carries a checksum record. Both accumulate into a
14 * caller-owned stats block and invoke an optional per-mismatch report.
15 *
16 * WHY: CSI's hot read path only verifies the blocks a read FULLY spans, so a
17 * corrupt block in cold data is never noticed until something reads it.
18 * A periodic sweep surfaces at-rest rot proactively (metrics + error.log
19 * DIAG) rather than on the unlucky client's read. This is the deferred
20 * W2b half of the CSI workstream.
21 *
22 * HOW: Pure engine — no nginx runtime; libc + fs/meta/xmeta + crc32c only, so
23 * it compiles standalone (see tests/c/test_csi_scrub.c). The pacing is
24 * the CALLER's job: brix_csi_scrub_interval arms a per-server maintenance
25 * timer that runs one walk per interval (never a self-rearming hot poll).
26 * A record's own buffer_size is the granule; a slot of 0 (BRIX_XMETA_
27 * CRC_UNSET) is "not computed" and skipped (fail-open on coverage);
28 * a block whose recorded range is short on disk is skipped, never failed
29 * (fail-closed only on an actual CRC difference).
30 */
31
