1/*
2 * Site checksum plugins — host side of core/compat/checksum_plugin_abi.h.
3 *
4 * WHAT: a process-wide registry of dlopen()ed checksum algorithms, filled by
5 * the `brix_checksum_plugin` directive (stream + http main level) and read by
6 * the name parser (core/compat/checksum.c), the Qconfig `chksum` list and the
7 * digest walker. Plugin algorithms occupy brix_checksum_alg_t values from
8 * BRIX_CHECKSUM_PLUGIN_BASE upward so every existing switch keeps its default.
9 *
10 * WHY: XRootD sites carry `xrootd.chksum` externals; a 2.0 site must be able
11 * to answer a non-built-in algorithm without a fork of the server (2.0
12 * readiness F8). INVARIANT 9 stays intact: the host hex-encodes at the edge.
13 *
14 * The registry is keyed on the cycle like the DNS target registry: the first
15 * directive of a new cycle drops (dlclose) whatever the previous configuration
16 * loaded, and the worker init hook drops it when the new configuration
17 * declares no plugin at all.
18 */
