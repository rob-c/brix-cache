33/* Does the storage backend resolved for this ctx consume a forwarded X.509 proxy
34 * PEM (BRIX_SD_CRED_PROXY_PEM in its cred_accept mask)? Lets a protocol gate a
35 * default-on proxy delegation to only the backends that can actually use it

37 * so binding a proxy bag there never turns into a spurious cred-gate deny.

51/* Allocate a delegation live-cred bag from `pool`, populate it with the captured
52 * forwardable credential BYTES, and bind it onto `vctx` (phase-70 §5.1/§5.4).
53 *
54 * `mode` is the export's resolved brix_cred_mode (conf->common.backend_delegation);
55 * when it is BRIX_CRED_SELECT this is a no-op (the ctx stays on the dir-based
56 * SELECT path). `bearer` is the raw JWT text (or {0,NULL} when none was captured);

61 * single constructor so the struct layout stays private to the VFS. Defined in
62 * vfs_deleg.c. */

67/* Populate the EXCHANGE conf on the ctx's bound live-cred bag (phase-70 §5.4).
68 * Call at capture time, AFTER brix_vfs_deleg_bind, when the export's mode is
69 * BRIX_CRED_EXCHANGE: `endpoint`/`client_id`/`client_secret` come from
70 * conf->common.backend_tx_* and `audience` from the first backend_token_aud
71 * entry. All strings are borrowed (conf-owned, NUL-terminated) and must outlive
72 * the VFS op. `tx_cache_slot` (optional, may be NULL) is the address of the
73 * conf's `backend_tx_cache` pointer — the gate lazily creates the per-worker

75 * the export's phase-116 resolver policy (NULL: libc), pins the endpoint host.
76 * A no-op when no bag is bound or `endpoint` is empty — the cred gate then
77 * degrades EXCHANGE to verbatim bearer passthrough. In vfs_deleg_bind.c. */

84/* Bind the export's trusted CA store onto the ctx's bound live-cred bag so the

96/* Arm SSS identity injection on the ctx (phase-70 §5.6 / P90-70.3): when the
97 * request carries NO forwardable credential bytes, the cred gate materialises
98 * an SSS credential asserting the caller's authenticated principal, signed
99 * with `keytab` (conf->common.backend_sss_keytab; borrowed conf bytes,
100 * NUL-terminated). Proven bytes (proxy PEM / bearer) always win over
101 * injection. Unlike the other setters this ALLOCATES the bag (from vctx->pool)
102 * when none is bound — injection is precisely the no-captured-bytes case where
103 * brix_vfs_deleg_bind declined to bind. A no-op when `mode` is
104 * BRIX_CRED_SELECT or `keytab` is empty; on bag-allocation OOM it degrades to
105 * SELECT exactly like brix_vfs_deleg_bind's no-bytes path. Defined in
106 * vfs_deleg_bind.c. */
107void brix_vfs_deleg_set_sss(brix_vfs_ctx_t *vctx, enum brix_cred_mode mode,

110/* Arm S3 STS credential EXCHANGE on the ctx (phase-70 §5.5): when the request
111 * carries NO forwardable credential bytes and the leaf backend accepts an S3
112 * credential, the cred gate exchanges the node's S3 SERVICE credential for
113 * temporary (ak/sk/session) creds scoped to the caller's identity via STS
114 * AssumeRole/GetSessionToken. `cf` is a borrowed brix_s3_sts_conf_t built from
115 * conf->common.backend_sts_* (its ngx_str_t fields point at conf-owned bytes;
116 * the struct itself must outlive the VFS op — build it on the request pool).
117 * Like brix_vfs_deleg_set_sss this ALLOCATES the bag (from vctx->pool) when none
118 * is bound — STS, like SSS, is precisely the no-captured-bytes case. A no-op
119 * when `mode` is BRIX_CRED_SELECT or `cf` is NULL; on bag-allocation OOM it
120 * degrades to SELECT. Defined in vfs_deleg_bind.c. */

124/* Arm krb5 GSSAPI EXCHANGE on the ctx (phase-70 §5.7): the front door has
125 * captured the caller's forwarded TGT and serialised it to a 0600 FILE ccache

127 * derived origin service principal onto the bag. When the leaf backend accepts

133 * bag-allocation OOM it degrades to SELECT. Defined in vfs_deleg_bind.c. */
