1/*
2 * dns.h — runtime DNS for BriX (phase-116): resolv.conf-driven resolver
3 * policy, the async resolve driver, the per-worker answer cache, the
4 * thread-to-loop bridge, and the config-time target registry that lets every
5 * brix hostname be parse-only at `nginx -t` and resolved (and re-resolved)
6 * at runtime.
7 *
8 * WHAT: One public surface for the layers under src/net/dns/:
9 * policy — brix_dns_policy_t built by `brix_resolver auto` from the
10 * resolv.conf the process can see (resolver_build.c),
11 * driver — brix_dns_resolve(): async, search/ndots-aware, cached;
12 * nginx's resolver when one is in scope, else a thread-
13 * pool getaddrinfo (resolve.c / resolve_thread.c),
14 * sync — brix_dns_resolve_sync(): the ONE blocking entry point
15 * for thread-pool code; literal -> cache -> bridge to the
16 * event loop's resolver -> libc (resolve_thread.c),
17 * bridge — resolve_bridge.c: an eventfd-woken queue that lets a
18 * thread-pool task use the loop's nginx resolver,
19 * cache — positive + negative per-worker cache (cache.c),
20 * targets — brix_dns_target_t: a directive's hostname registered at
21 * parse time, resolved from init_process with backoff,
22 * refreshed on TTL expiry / failure, rotated round-robin
23 * (targets.c),
24 * curl pin — curl_pin.h: CURLOPT_RESOLVE pinning so libcurl never
25 * resolves on its own,
26 * reverse — brix_dns_reverse*(): PTR lookups (XrdAcc host rules,
27 * protbind templates, `host` auth, the TPC origin id)
28 * with their own address-keyed cache: cached-only probes
29 * for the event loop, async fills, a blocking flavour for
30 * threads (reverse.c / reverse_cache.c),
31 * prefetch — brix_dns_lookup_cached() / brix_dns_prefetch(): the
32 * never-blocking forward probe the event loop uses for a
33 * TPC source preflight (prefetch.c).
34 * WHY: nginx open-source resolves hostnames once at parse time (a dead name
35 * is a fatal `nginx -t` error) and never reads resolv.conf; nginx Plus
36 * re-resolves but still needs a hand-written `resolver`. brix closes
37 * both gaps: no hostname may stop the server starting (I-DNS-1), and
38 * resolution always follows the visible resolv.conf (I-DNS-2/3).
39 * HOW: Everything async lives on the event loop; the libc resolver is called
40 * in exactly one place (resolve_thread.c) and never on the event loop
41 * except for the deadline-bounded OCSP transaction the GSI handshake
42 * already performs inline (I-DNS-4, guard tools/ci/check_dns_seam.py —
43 * strict, no allow-markers, no backlog). The registry, the cache and
44 * the bridge are per-process singletons following the origin_probe
45 * precedent (config-time statics that survive the fork).
46 */
