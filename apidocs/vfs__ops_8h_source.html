265/* --- unified verified write session (src/fs/vfs/vfs_writer.c) ------------------
266 * ONE write entry point for every backend: a protocol write path (GridFTP STOR,
267 * and any future caller) opens a session, feeds extents, and commits — the
268 * session picks the mechanics from the backend's capabilities and, when asked,
269 * folds a self-computed CRC that is verified against a read-back on commit.
270 *
271 * random-write backend (POSIX default export, pblock): an in-place
272 * O_WRITE|O_CREATE handle written with brix_vfs_file_pwrite at arbitrary
273 * offsets — REST/APPE and out-of-order (MODE E) extents are supported.
274 * staged-only backend (S3/object store, no CAP_RANDOM_WRITE): an atomic
275 * staged upload (temp → commit); extents MUST arrive sequentially from
276 * offset 0 (an object store cannot patch bytes in place), so a non-sequential
277 * write is refused.
278 *
279 * `verify` asserts the caller is writing a whole object from offset 0 (a fresh
280 * STOR, not a REST/APPE partial); when set, every extent is CRC-32'd and, on
281 * commit, the persisted object is re-read through its driver and compared. A
282 * mismatch/short object unlinks the file and fails the commit. An empty object
283 * (nothing written) is a complete [0,0) write and verifies trivially. */
