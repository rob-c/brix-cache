1/*
2 * store_policy.h — signing_policy table + X509_STORE ex_data binding.
3 *
4 * WHAT: Builds a per-CA-directory table of parsed signing_policy files and
5 * attaches it (with the operator's whole brix_trust_policy_t — signing
6 * policy, CRL mode, CRL scope, verification-log level) to an X509_STORE,
7 * so the shared verifier and every store-rebuild path inherit
8 * enforcement from a single place.
9 * WHY: The verifier (brix_gsi_verify_chain) must decide "may this CA sign
10 * this subject?" without threading extra parameters through every
11 * caller. Binding the table to the store lets the decision travel with
12 * the trust material — including the stream CRL-reload rebuild and the
13 * WebDAV build-once path, which do not share a config object.
14 * HOW: ngx-free at its core (uses signing_policy.h + libc); the OpenSSL glue
15 * lives here. Logging is via a caller-supplied callback so no ngx
16 * symbol is required. The store owns the attached table and frees it.
17 */

31/*
32 * CRL SCOPE — how far up the chain the revocation check reaches. This is
33 * XRootD's `xrd.tlsca ... crlcheck all|last` residual.
34 *
35 * ALL (default) every certificate in the chain must be covered by a CRL
36 * its issuer published, and none of them may be listed on it.
37 * LAST only the CREDENTIAL'S OWN end-entity certificate is held to
38 * that; a revocation verdict on an issuer ABOVE it (a missing,
39 * stale or unverifiable CA CRL — or a revoked intermediate) is
40 * tolerated.
41 *
42 * IT IS NOT IMPLEMENTED BY DROPPING X509_V_FLAG_CRL_CHECK_ALL, and that is a
43 * security property, not an implementation detail. OpenSSL's plain CRL_CHECK
44 * checks depth 0 only, AND OpenSSL skips proxy certificates when it walks for
45 * revocation — so on a GSI proxy chain (proxy at depth 0, the EEC at depth 1)
46 * plain CRL_CHECK checks NOTHING AT ALL. Measured on OpenSSL 3.0.18 with
47 * `openssl verify -allow_proxy_certs`: `-crl_check` accepts a proxy whose EEC
48 * the CA has revoked; `-crl_check_all` refuses it at depth 1. A `last` built
49 * on the flag would therefore have been indistinguishable from `off` for every
50 * grid login — a revoked user would only have to wrap their credential in a
51 * proxy.
52 *
53 * So brix keeps CRL_CHECK|CRL_CHECK_ALL armed under BOTH values and narrows
54 * the scope in the verify callback instead: under LAST a revocation-class
55 * verdict counts only at the end-entity depth (the shallowest NON-proxy
56 * certificate in the chain), and is tolerated at every other depth. A revoked
57 * end-entity certificate is therefore refused under BOTH values, which is the
58 * invariant this knob is not allowed to break. What LAST actually buys is the
59 * deployment whose upstream CAs publish no usable CRL for their own issuers.
60 * Non-revocation verdicts (expiry, signature, untrusted issuer) are untouched
61 * at every depth under both values.
62 */
63#define BRIX_CRL_SCOPE_ALL 0 /* every certificate in the chain (default) */
64#define BRIX_CRL_SCOPE_LAST 1 /* the end-entity certificate only */
65
66/*
67 * VERIFICATION LOG — the `xrd.tlsca ... verifylog` residual. OFF is silent
68 * (brix's historical behaviour: only the module's own one-line rejection).
69 * FAILURE adds, on a rejected chain, the depth at which OpenSSL stopped and
70 * the subject DN of the certificate that failed. ALL additionally records the
71 * subject DN of every certificate in an ACCEPTED chain.
72 *
73 * DNs ONLY. The log never emits key material, a PEM body, or any certificate
74 * bytes — an operator diagnosing "which CA did this chain actually come
75 * through?" needs names, and the error log is not a place to widen what an
76 * attacker who can read it learns (see the security negative in
77 * tests/test_release20_tlsca_residuals.py).
78 */
79#define BRIX_TLS_VERIFY_LOG_OFF 0
80#define BRIX_TLS_VERIFY_LOG_FAILURE 1
81#define BRIX_TLS_VERIFY_LOG_ALL 2

85/*
86 * WHAT: the complete trust-enforcement policy that travels with an X509_STORE.
87 * WHY: the store is built in one place (config parse, or a CRL-reload timer)
88 * and consulted in another (a verify callback, brix_gsi_verify_chain)
89 * that has no config object. Passing the four knobs as one value keeps
90 * the store builders' signatures stable as knobs are added, and — more
91 * importantly — makes it impossible to add a knob that reaches
92 * brix_store_configure but never reaches the ex_data the verifier reads.
93 * HOW: initialise with BRIX_TRUST_POLICY_INIT (everything off / widest scope)
94 * and set the fields the caller actually configures.
95 */

185/*
186 * Per-certificate WLCG/IGTF conformance policy applied to every cert in a
187 * verified chain: minimum key strength (RSA >= 2048, EC >= 256), no weak
188 * signature algorithm (MD5/SHA-1), a well-formed serial number (positive,
189 * <= 20 octets, RFC 5280 §4.1.2.2), and no embedded control/NUL bytes in the
190 * subject/issuer DN (RFC 5280 §4.1.2.6). Returns 1 when the cert violates
191 * policy, 0 when it is clean. Proxy certificates are exempt from the serial
192 * ceiling (grid proxies routinely use large timestamp-derived serials).
193 */

200 * keyUsage it must assert digitalSignature (§4.2.1.3). Returns 1 on violation,
