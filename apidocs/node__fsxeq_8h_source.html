4/*
5 * node_fsxeq.h — 2.0 F17: the operator program that REPLACES this data node's
6 * built-in execution of a manager-forwarded namespace op (stock cms.fsxeq).
7 *
8 * WHAT: brix_cms_fsxeq_dispatch() is consulted once per forwarded op, after the
9 * read-only mutation gate and before the storage leg is chosen. When the
10 * op has no program the caller keeps its built-in leg unchanged; when it
11 * has one, this file owns the whole rest of the op — validation, the run,
12 * and the cmsd-shaped reply.
13 * WHY: a site's namespace semantics (catalogue update, quota hook, tape-aware
14 * unlink) may not be POSIX. The refusal this reverses was made on
15 * performance and blast-radius grounds, so both constraints survive as
16 * requirements: the program NEVER runs on the worker's own thread, and it
17 * is never handed a path the built-in leg would have refused.
18 * HOW: the run is one brix_subprocess_run() on an nginx thread-pool task —
19 * that runner puts the program under a double-forked agent (nginx's
20 * master would otherwise reap a worker's direct child and steal the exit
21 * status), in its own session, with every inherited descriptor closed,
22 * and it SIGKILLs the program's whole process group at
23 * brix_cms_fsxeq_timeout. The completion handler answers the manager on
24 * the event loop; a program that hangs costs one thread-pool slot and one
25 * forwarded op, never the worker.
26 */
