1/*
2 * brix_fault_proxy_mods.h — first-party optional modules that bolt onto the
3 * brix-fault-proxy core (brix_fault_proxy.c) without reaching into its private
4 * fault-lever state. Each module is a self-contained translation unit; the core
5 * calls these entry points and nothing else crosses the boundary.
6 *
7 * ctl — a built-in control-port client subcommand (`brix-fault-proxy
8 * ctl <host:port> "<cmd>"`), replacing the external `nc` that
9 * operators and tests used to shell out to.
10 * event-log — an optional append-only JSONL trail of discrete fault events
11 * (sever, refuse), giving per-event provenance the point-in-time
12 * `status`/metrics aggregates cannot.
13 *
14 * These are deliberately decoupled from the core's static lever_t / counters:
15 * the event sink takes only plain scalars, so it links against no core symbol
16 * and the core only ever calls brix_fp_event() / fp_event_open().
17 */
