4/*
5 * offload_registry.h — per-worker (sessid, pathid) -> secondary-connection map
6 * for pathid response offloading (audit §1.1/§7.3, do_Offload parity).
7 *
8 * WHAT: an in-process table the kXR_bind handler fills when a secondary data
9 * channel binds (register), the disconnect path clears when it goes away
10 * (unregister), and — in a later slice — the read/readv handler consults
11 * (lookup) to route a pathid-tagged response out the SECONDARY connection's
12 * socket instead of the control stream.
13 *
14 * WHY: the SHM session registry already tracks WHICH pathids a session has bound
15 * (brix_session_pathid_bound, cross-worker), but response offloading needs
16 * the actual per-worker `ngx_connection_t` of the secondary to send data on
17 * it — and a connection object is process-local, so it cannot live in SHM.
18 * This is that process-local half.
19 *
20 * HOW: a fixed-capacity array keyed by (sessid[BRIX_SESSION_ID_LEN], pathid).
21 * The connection is stored as an opaque `void *` so the table carries no
22 * nginx dependency and is unit-testable with plain pointers. Single-worker
23 * event loop = no locking. A secondary that binds while the table is full
24 * simply is not registered (offloading silently falls back to the control
25 * stream for it — never an error).
26 *
27 * SCOPE: this slice only maintains the table (bind fills it, disconnect clears
28 * it); nothing consults it yet, so the data path is unchanged. The routing
29 * that consumes lookup() lands in the next slice.
30 */
31
