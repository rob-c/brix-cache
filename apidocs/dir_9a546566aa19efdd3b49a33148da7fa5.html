Detailed Description

Filesystem client entry points

The default xrootdfs driver uses libfuse's low-level interface on every host. Kernel node IDs belong to mount-local inode objects, not individual pathnames. The root and read-only HTTP transports share this adapter. The explicitly selected legacy driver remains separate.

The registry permits at most 65,536 live nodes, 262,144 aliases and 64 MiB of alias strings per mount. Reservations count against those limits before a server mutation. Namespace operations serialize with alias changes; handle reads/writes use the existing per-handle I/O locks and remain parallel. Lookup and open owners are independent: forget, unlink and rename cannot free a live handle's inode. Known server identities remain stable across cache eviction; new registry owners receive monotonically advancing generations. Unknown web identities use checked path-derived candidates, never hash-based alias merging.

Directory snapshots have a separate 64 MiB per-open bound. Their advisory unknown directory inode is nonzero; only a successful lookup/entry reply grants a kernel inode reference. Directory cursors are encoded by libfuse itself.

The kernel request's UID is passed explicitly to metadata and open operations. Per-caller SSS mounts disable shared attribute/entry and file-page caching; failed identity acquisition never uses the mount owner's connections.
