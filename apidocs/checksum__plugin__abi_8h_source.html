1/*
2 * brix checksum plugin ABI (site-facing).
3 *
4 * A site that needs a checksum algorithm the seven built-ins (adler32, crc32,
5 * crc32c, crc64, crc64nvme, md5, sha1, sha256, sha512) do not cover compiles a
6 * shared object against THIS header only and registers it with
7 *
8 * brix_checksum_plugin <name> /abs/path/plugin.so [parms];
9 *
10 * The object exports one data symbol, `brix_cks_plugin`, of type
11 * brix_cks_plugin_t. The server dlopen()s it at config time (RTLD_NOW|RTLD_LOCAL),
12 * validates every field, runs an empty-input self-test and refuses the config
13 * on any mismatch — a broken plugin never reaches a worker.
14 *
15 * Streaming contract (one state per computation, never shared):
16 * init(state, parms) -> 0 on success; `parms` is the directive's third
17 * argument or "" when absent.
18 * update(state, buf, n) -> 0 on success; called in file order with the
19 * bytes of the object, n may be 0.
20 * final(state, digest) -> 0 on success; writes exactly digest_len bytes.
21 *
22 * The host hex-encodes `digest` itself (lowercase, 2*digest_len characters),
23 * so a plugin never touches the wire; every protocol (kXR_query cks, WebDAV
24 * Want-Digest, Qconfig chksum) sees the plugin under the registered name.
25 *
26 * The header is plain C99 with no server dependencies on purpose: a plugin
27 * must build outside the nginx tree.
28 */
