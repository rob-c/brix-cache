1/*
2 * gcas.h — phase-87 G13: cross-repo dedup of verified CVMFS CAS objects.
3 *
4 * WHAT: hardlink-identity dedup for the LOCAL posix cache store — every
5 * cvmfs-cas-verified /cvmfs/<repo>/data/ object also carries a canonical
6 * repo-agnostic name under <store>/.gcas/, so byte-identical objects
7 * referenced by several repos share ONE inode.
8 * WHY: stratum mirrors publish the same objects under many repo prefixes and
9 * the cache key is the client-visible per-repo path, so identical
10 * content was stored once per repo. Content addressing plus the
11 * verify-on-fill proof make hash identity safe to collapse — but only
12 * at the byte layer: keys, cinfo records, authz and origin fetches stay
13 * strictly per-repo, so a repo can never serve bytes its own origin has
14 * not proven it holds (each repo still fills — and 404s — through its
15 * own origin; dedup begins only after that verified fill commits).
16 * HOW: publish (post-commit, cvmfs-cas-verified fills only) links the
17 * committed object and the canonical name onto one inode; evict GC
18 * unlinks the canonical once it is the last remaining name. The
19 * filesystem's link count IS the combined refcount — a shared object
20 * survives until its last per-repo reference is evicted and there is no
21 * bookkeeping to corrupt or double-free. Every step is best-effort: any
22 * failure leaves plain, correct per-repo copies.
23 */
