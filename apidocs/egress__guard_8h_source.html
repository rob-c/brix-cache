4/*
5 * egress_guard.h — TPC source-host egress allowlist (SSRF policy control).
6 *
7 * WHAT: an operator-configured allowlist of hostnames a gateway is permitted to
8 * originate a third-party-copy *pull* from. In the TPC-pull model the
9 * destination (this gateway) is the party that dials the named source host, so
10 * an un-guarded gateway is a request-forgery primitive: any client that can
11 * open a TPC destination can steer the server's outbound socket at an
12 * arbitrary host. This guard refuses to originate unless the source host
13 * matches the allowlist.
14 *
15 * WHY: the pre-existing address-range gate (brix_tpc_check_src_policy →
16 * allow_local/allow_private) only rejects loopback/private *addresses*; it
17 * cannot express "only these known storage endpoints". Naming-based policy is
18 * the complementary control operators actually want, mirroring the reverse-DNS
19 * host allowlist already used by the `host` auth scheme (brix_host_allow).
20 *
21 * HOW: the pattern match is pure C (no nginx, no allocation) so it unit-tests
22 * standalone; the nginx wrappers iterate the ngx_array_t of configured
23 * patterns and render the kXR_NotAuthorized-grade refusal text. Refusal is
24 * fail-closed and default-deny: when the guard is on, an empty allowlist
25 * permits nothing. The guard is a no-op (returns "allow") when off, so it
26 * never changes behaviour for deployments that do not opt in.
27 */
