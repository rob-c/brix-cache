25/*
26 * server_auth.c — CMS registration authentication (Phase 28 W1).
27 *
28 * WHAT: Authentication/authorisation gates applied to a data node before it is
29 * allowed into the manager's server registry (and therefore before the
30 * manager will redirect clients to it). Two alternative/composable
31 * admission controls plus unconditional host validation, all compatible
32 * with vanilla XRootD:
33 * W1a — real cmsd sss credential check (kYR_xauth handshake), reusing
34 * the shared SSS verifier in src/sss.
35 * W1b — accept-time CIDR allowlist of permitted data-node IPs.
36 * W1c — host-character validation at registration store time
37 * (brix_net_host_chars_valid, called from registry.c).
38 *
39 * WHY: Without these, any peer that can reach the CMS port can self-report an
40 * arbitrary host:port:paths and have the manager redirect clients to it
41 * (redirect poisoning — the critical finding). At least one control is
42 * mandatory: a vanilla cmsd from a trusted subnet can use W1b alone,
43 * while W1a provides cryptographic cluster authentication.
44 */
