1/*
2 * vfs_secgate.h — generic per-capability TLS gating (the VFS security gate).
3 *
4 * WHAT: The capability mask (BRIX_TLSREQ_LOGIN/SESSION/DATA/TPC), the pure
5 * parser for the `brix_tls_require` directive grammar
6 * (`none | [all|login|session|data|tpc]... [-cap]...`), the pure
7 * gate check brix_tls_gate_refused(), the cap-name helper for error
8 * messages, and the shared offset-based conf setter used by both the
9 * stream (root://) and HTTP (WebDAV/S3/cvmfs) directive tables.
10 *
11 * WHY: Stock XRootD gates TLS per capability (`xrootd.tls login/session/
12 * data/tpc` with `-cap` exceptions); BriX only had the coarse
13 * brix_min_sec_level floor. Implementing the mask + grammar + check
14 * once at the VFS layer means every plane (stream opcodes, WebDAV
15 * methods, S3 requests, native + WebDAV TPC) enforces identical policy
16 * from one `common.tls_require` field instead of four re-implementations.
17 *
18 * HOW: Parser and check are side-effect-free (testable without a server):
19 * tokens are folded left-to-right into a 4-bit mask; `all` sets every
20 * bit, `-cap` clears one, `none` must stand alone. The gate returns the
21 * set of REQUIRED-but-unmet bits (0 = allowed) so callers can name the
22 * refused capability in kXR_TLSRequired / 403 messages. The conf setter
23 * writes the parsed mask through cmd->offset, so one function serves
24 * ngx_http_brix_common_conf_t and ngx_stream_brix_srv_conf_t alike.
25 */
