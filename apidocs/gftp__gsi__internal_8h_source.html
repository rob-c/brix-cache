4/*
5 * gftp_gsi_internal.h — the GSI context shared by the control channel and a
6 * PROT P data channel.
7 *
8 * WHAT: the layout of gftp_gsi_t plus the two construction primitives
9 * (gftp_ssl_error, gftp_gsi_setup) that build a client TLS context carrying the
10 * X.509 proxy chain and the CA-directory trust anchors.
11 *
12 * WHY: a GridFTP protected data channel (DCAU A + PROT P) is a straight TLS
13 * session on the data socket presenting the SAME proxy the control channel
14 * authenticated with — see src/protocols/gridftp/ftp_dc_sec.h for the
15 * inbound mirror of this fact. The credential loading is therefore the
16 * same code for both, and duplicating it would let the two drift on
17 * exactly the thing that must not drift: which certificate BriX presents
18 * and which roots it trusts. This header exists only so the data-channel
19 * file (gftp_dc_tls.c) can reuse it; nothing outside this directory
20 * includes it.
21 *
22 * HOW: gftp_gsi.c owns the definitions; gftp_dc_tls.c calls gftp_gsi_setup()
23 * on a freshly calloc'd context and then attaches a socket BIO instead of
24 * the control channel's memory BIO pair.
25 */
