4/*
5 * admin_socket.h — §1.16 runtime admin unix socket (XrdXrootdAdmin analog).
6 *
7 * WHAT: a worker-0 unix-domain control socket (`brix_admin_socket <path>`)
8 * speaking a line-based command protocol:
9 * list -> ok <n>\n then one "<sessid-hex> <dn|->" line each
10 * disc <sessid-hex> -> ok | err ... (shutdown()s the session's conn)
11 * msg <sessid-hex> <t> -> ok | err ... (kXR_attn/asyncms to the client)
12 * pause <sessid-hex> [<secs>] -> ok | err (stop reading its requests;
13 * in-flight replies drain; optional auto-resume)
14 * cont <sessid-hex> -> ok | err ... (resume a paused session)
15 * abort <sessid-hex> -> ok | err ... (RST-close: SO_LINGER{1,0})
16 * Replies end with a newline; errors are "err <reason>".
17 *
18 * WHY: stock's XrdXrootdAdmin socket lets an operator inspect and control live
19 * sessions without restarting the server. The stock admin wire grammar is
20 * not published in installed headers, so this speaks a DOCUMENTED-DIVERGENT
21 * simple text protocol with the same operational verbs.
22 *
23 * HOW: sessions self-register in the per-worker offload registry under
24 * BRIX_ADMIN_PATHID at connection setup; the admin TU resolves
25 * sessid -> conn there (disc = shutdown(2) so the normal event-loop
26 * teardown runs; msg = brix_send_attn_asyncms on the target's out-ring)
27 * and enriches `list` with the peer address and the SHM registry's dn.
28 * MULTI-WORKER: every worker serves its own socket — worker 0 at <path>,
29 * worker n at "<path>.<n>" — each listing/controlling exactly the sessions
30 * its worker owns (an admin tool sweeps the set). The natural mapping of
31 * stock's single-daemon adminpath onto nginx's process model.
32 *
33 * SECURITY: the socket is chmod 0600 (owner-only) and carries NO in-band auth —
34 * filesystem permission on the path IS the privilege boundary, exactly like
35 * stock's adminpath.
36 */
