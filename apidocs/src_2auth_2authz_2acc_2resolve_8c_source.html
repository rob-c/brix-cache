1/*
2 * resolve.c — reverse-DNS the peer for `h <host>` / `h .domain` rule matching
3 * (XrdAccAccess::Resolve).
4 *
5 * WHAT: A never-blocking probe of the phase-116 reverse-DNS cache for the
6 * peer's FQDN. NGX_OK fills `buf` with the name; NGX_DECLINED means the
7 * address has no PTR record (or is not an IP address at all) so the
8 * caller keeps the numeric peer; NGX_AGAIN means the answer is not known
9 * yet — a background fill has been started so the next probe can answer.
10 * WHY: Every caller sits on the event loop (XrdAcc host rules, protbind host
11 * templates, `host` authentication), where the old getnameinfo() stalled
12 * the whole worker — the Phase 51 circuit breaker only bounded how often.
13 * Phase 116 moved the lookup off the loop: the stream accept path
14 * (connection/peer_name.c) and the HTTP PREACCESS phase
15 * (core/http/http_peer_name.c) wait for the answer before any rule runs,
16 * so by the time a decision is made this probe is a cache hit. The
17 * AGAIN arm stays for callers reached without a wait (a hot reload that
18 * enabled the policy mid-session, an eviction between accept and the
19 * decision): they fall back to the numeric peer, and the fallback is
20 * counted so an operator can see it happening.
21 * HOW: brix_dns_reverse_cached() → on NGX_AGAIN, brix_dns_reverse_prefetch()
22 * under the server's DNS policy + BRIX_RESIL_METRIC_INC. No state of
23 * its own: the cache in src/net/dns owns TTLs, negative answers and the
24 * in-flight markers, and it answers NGX_DECLINED for a non-IP peer.
25 */
