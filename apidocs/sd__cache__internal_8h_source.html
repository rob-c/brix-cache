66/* Fill `key` from the source into the cache store and record its cinfo. NGX_OK
67 * (cached or stale-served), NGX_DECLINED (admission), NGX_ERROR. `cred` may be
68 * NULL (service-credential path). Called by the interposed read-open miss path
69 * and the async fill-key entrypoint in sd_cache.c.
70 *
71 * `allow_pt` opts this fill into the phase-92 store-then-evict passthrough: an
72 * admission-declined object within the passthrough cap is filled anyway and the
73 * call returns NGX_OK with *out_pt=1, signalling the caller to evict the key
74 * once it has served the object as a transient hit. When `allow_pt` is 0 (or
75 * the policy has passthrough off / the object exceeds the cap) an admission
76 * decline still returns NGX_DECLINED. `out_pt` may be NULL. */

89/* ---- CVMFS manifest/whitelist signature verify (sd_cache_manifest.c) ----- */
90
91/* Phase-85 F1: verify a MANIFEST-class staged fill before commit when the
92 * repo master public key is configured (policy.cvmfs_master_pub):
93 * .cvmfspublished — full chain: whitelist sig vs master key → whitelist not
94 * expired → manifest cert fingerprint ∈ whitelist → manifest sig vs cert
95 * (whitelist + certificate fetched through the fill's source tier);
96 * .cvmfswhitelist — signature vs master key + expiry.
97 * Returns NGX_OK (verified, or key is not a signed-metadata shape / verify not
98 * configured — commit proceeds); NGX_ERROR (verification definitively FAILED —
99 * the caller emits signal=cvmfs_tamper, quarantines, aborts, EBADMSG); or
100 * NGX_DECLINED (the chain could not be evaluated — sibling fetch / part read
101 * failed; the caller fails the fill closed with EIO, NO tamper signal, so an
102 * origin outage never feeds the maxretry=1 tamper jail). `pp` is the staged
103 * part path. */

126 * window off the read cursor on every sequential read; this ratchet makes
