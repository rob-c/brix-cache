Modular WLCG storage interface

Every protocol.
Every backend.
One VFS plane.

BriX-Cache teaches one nginx binary to serve a single POSIX namespace over root:// davs:// s3:// and gsiftp://. Every protocol and every auth scheme — GSI/x509, WLCG tokens, S3 SigV4, Kerberos, SSS — meet at one unified VFS plane that fans out to any storage backend: POSIX, Ceph, an S3 or block store, or an upstream xrootd — all under the same namespace.

gsiftp://

A full peer protocol for GridFTP.

A complete gsiftp:// server terminates in the same binary — GSI / x509 control-channel auth, parallel MODE E data streams, encrypted (PROT P) data channels, and server-to-server third-party copy. Like the other three it terminates on the shared VFS, so it serves any storage backend — POSIX, an S3 or Ceph object store, or a block store — across the very same namespace root://, WebDAV, and S3 serve. Write a file with globus-url-copy, gfal2, or FTS and read it back byte-for-byte over any door.

Signal path

Four fronts in, one path to disk.

Every protocol enters through nginx's event loop, funnels through one shared core that handles auth, path confinement, caching, and metrics — then reaches storage. No worker ever blocks: disk syscalls run on a thread pool while the worker keeps serving.

  1. 01 · ingress clients xrdcp · curl · aws-cli

  2. 02 · event loop nginx module epoll · non-blocking
    →
  3. 03 · shared core auth · confine · cache metrics · path resolve
    →
  4. 04 · egress VFS backend POSIX · root:// · Ceph
Trust & readout

WLCG-native auth, checked before a byte moves.

GSI / x509 proxy certs with kXR_sigver request signing, VOMS, and WLCG bearer tokens with per-path scope enforcement (storage.read / write / create). Plus SSS, host allowlist, password, and Kerberos 5.

Every request is a metric and a log line.

One Prometheus /metrics endpoint covers every protocol — the zone is process-wide, so the planes served from stream {} land in the same exposition as the HTTP ones, under one proto label. Fixed, low-cardinality labels — no per-file or per-user explosion. Structured access logs for every protocol, and a live HTTPS operator dashboard at /brix/.
